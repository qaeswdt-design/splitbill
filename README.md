# 聚會拆帳記帳系統（Python）

朋友聚會結帳時，把一筆筆消費拆給參與的人，再算出**轉帳筆數最少**的結清方式。
只用 Python 標準庫（不需要 `pip install` 任何套件），有命令列介面，也能開成網頁版讓同一個區域網路的手機直接使用。

> 同一個專案的 Android 原生版（離線、可拍照掃描收據）：`splitbill-android`（另一個倉庫），兩邊使用同一種帳本格式，檔案可以互相匯入。

## 功能

- **朋友與代號**：每位朋友有短代號（`1`、`2`…），輸入時不用打全名；可建立常用群組，一次選入全部成員
- **三種拆帳方式**：平均分攤、依比例分攤、自訂每人金額；金額欄位可直接輸入算式（例如 `42+48+52`、`42*2+48`）
- **最少轉帳建議**：自動算出誰該轉給誰、轉多少，筆數最少
- **轉帳需收款方確認**：登記轉帳後，要收款方按「確認收到」才會計入餘額，也可以標示「沒收到」
- **可更正**：消費、轉帳、朋友都能刪除；已有紀錄的朋友不能刪，避免帳目對不起來
- **每個會改動資料的操作，送出前都有 Y/N 確認**
- **網頁版**：`python main.py web` 啟動後，同一個 Wi-Fi 的手機用瀏覽器就能操作

## 快速開始

需要 Python 3（開發與測試使用 3.13），不需要安裝其他東西。

```bash
# 命令列版（選單操作）
python main.py

# 網頁版（預設 8000 埠，也可以指定，例如 python main.py web 9000）
python main.py web
```

網頁版啟動後，終端機會印出一組網址（含隨機存取金鑰 `?k=...`），用同一個網路的手機開啟即可。
Windows 也可以直接點兩下 `啟動網頁版.bat`。

> 網頁版會監聽所有網路介面，只適合在自己信任的區域網路使用，請不要直接暴露到網際網路。

## 執行測試

```bash
python -m unittest discover -s tests
```

目前 66 個測試，涵蓋拆帳、結算演算法、帳本規則、算式解析與網頁 API。

## 專案結構

```
main.py                 進入點（命令列 / web）
splitbill/
  models.py             資料結構（朋友、消費、轉帳）
  splitter.py           三種拆帳方式，處理尾差
  settlement.py         最少轉帳次數演算法
  ledger.py             帳本規則（餘額計算、轉帳確認、刪除限制）
  storage.py            帳本存成 JSON
  expression.py         金額算式解析（不使用 eval）
  cli.py                命令列選單
  web.py                網頁版（標準庫 http.server）
  static/index.html     手機版網頁介面（單一檔案）
tests/                  unittest 測試
```

## 設計重點

- **餘額用「淨額」計算**：每人餘額 = 先付的錢 − 應分攤的錢，再加減**已確認**的轉帳；沒確認或被標示沒收到的轉帳不計入。
- **金額一律用 `Decimal`**，避免浮點數誤差；平均與比例分攤要求整數金額，最後一位吸收尾差，保證每人分攤加總等於總額。
- **最少轉帳次數**：這是 NP-hard 問題，但朋友聚會人數很少。餘額不為 0 的人（要付或要收的人，已平帳的不算）≤ 10 位時用回溯法（DFS）窮舉出**真正最少**的筆數；超過時改用貪婪法（每次配對目前欠最多與該收最多的人，筆數上限 n−1），效能穩定但不保證最少。
- **算式解析不用 `eval`**：只接受數字、`+`、`*`（含 `x`、`×`），沒有執行任意程式碼的風險。
- **網頁版的簡單防護**：每次啟動產生隨機存取金鑰，用 `hmac.compare_digest` 比對；它是給朋友聚會短時間使用的，不是正式的帳號系統。

## 資料與隱私

帳本存在本機 `data/ledger.json`（已加入 `.gitignore`，不會被上傳）。沒有任何網路上傳，也沒有第三方服務。

## 已知限制

- 只做單一帳本，沒有使用者帳號與多人即時同步（網頁版同一時間共用同一份帳本）。
- 貪婪法在餘額不為 0 的人超過 10 位時，不保證轉帳筆數絕對最少。
- 命令列版與網頁版不要同時開啟，兩者會寫入同一份帳本檔。
